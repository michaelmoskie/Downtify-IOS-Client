Server implementation/deployment was not independently validated.

## Verified settings inventory and connection gates

This inventory is from the pinned Android UI/data sources, not an inferred iOS design. The `SettingsScreen` groups controls as follows:

- **Server card:** server name (session name, falling back to `/api/server/info` name), address, connection tag (`Connected`, `Checking`, `Unreachable`, or `Different server`), version tag only when known, and signed-in username only when nonblank. `Change server` opens the sign-out confirmation; `Open web` opens the base URL. The separate Server group contains the same sign-out action. Sign-out forgets the token locally and retains the synced library; removing the phone from the server's paired-device list is a separate web action.
- **Playback:** `Normalize volume` toggle; when on, `Playback level` offers Normal/Louder/Maximum. Wi-Fi quality always offers Original plus supported curated transcoding choices. Mobile-data quality uses the same list and is disabled with explanatory no-transcoding text when `capabilities.transcoding.available` is false. Android proposes Opus 96/128/160/256, AAC 128/192/256, and MP3 128/192/320, intersected with nonempty server format and bitrate lists; Original remains first. This is a curated subset, not every server-supported bitrate.
- **Buffering (its own group following Playback):** preload 0/1/2/3 upcoming tracks; temporary stream-cache limit from 10–200 MB in 10 MB steps (20 slider values; change is applied only after Apply); allow preloading on mobile data, disabled when track read-ahead is 0. Offline saved downloads are a separate cache from this temporary stream cache.
- **Downloads:** Wi-Fi-only downloads toggle; offline storage limit choices are decimal 1/2/4/8/16/32/64 GB or unlimited, with current offline bytes used shown in the summary.
- **Appearance:** System/Light/Dark theme; wallpaper color toggle only on Android 12/API 31+; pure-black AMOLED toggle; font choice Downtify classic/System/Google Sans Flex; floating navigation bar toggle; Android per-app Language row only on Android 13/API 33+ (delegates selection to system settings).
- **About:** About Downtify row includes app version and opens About. The separate About surface includes version/build, source, bug-report link, license, terms/disclaimer, and project support links. About/license content is a distinct surface rather than settings preferences.

The persisted settings model also has **library layout** (Grid/List), **library sort** (Recently added, Alphabetical, Artist), and **descending order**. These do not appear on the Settings screen: [LibraryScreen](https://github.com/henriquesebastiao/downtify-android/blob/100be83e49c3250424e6326670a73bff69325b73/app/src/main/kotlin/com/henriquesebastiao/downtify/feature/library/LibraryScreen.kt) exposes layout for non-Songs tabs and a sort bottom sheet for all tabs; the sort sheet offers Ascending/Descending and the three sort modes. Recently added defaults descending; picking a different sort resets to that sort's default direction. Songs are always list layout.

### Connect decision scenarios

1. `GET /api/server/info` is public and is the compatibility/capability source. `product != "Downtify"` is rejected; `api_version > 1` is rejected as too new. The documented contract says refuse newer API versions; this source does not define a lower bound for `api_version` or a minimum semantic server version.
2. On a supported server with `capabilities.password_sign_in=true`, connect proceeds to username/password; with it false or absent, it goes to pairing code. Pairing remains an explicit alternate on the sign-in step. Wrong password/code are distinct; `429 Retry-After` disables retry until countdown ends.
3. A scanned QR's base URL is preferred and its `sid` must equal the server's `server_id`; mismatch is shown as “other server” and no pair request is sent. A discovered server with API version above 1 is filtered from suggestions, but the user can still enter an address and receive the explicit too-new error.
4. Settings refresh probes the paired base URL. Matching server id and valid Downtify response means Connected and updates cached info/name; another server id, non-Downtify response, or too-new server means Different server; network/unreachable errors mean Unreachable. Last-known `/api/server/info` remains cached across launches so capabilities are still available offline.

### Linked server contract availability

The linked server repository and [its `docs/mobile-client-contract.md`](https://github.com/henriquesebastiao/downtify/blob/main/docs/mobile-client-contract.md) were accessible through the read-only GitHub connector at its default branch. It documents API version 1, `/api/server/info`, `capabilities.password_sign_in`, device-token scope and device-forbidden admin/settings operations. The Android pin `100be83e49c3250424e6326670a73bff69325b73` is an Android-repository commit and cannot pin a revision in the separate server repository; therefore this contract citation is explicitly **current default branch**, not a server snapshot paired to the Android commit. Server implementation and deployed-server behavior were not independently fetched or validated here. The existing `docs/server-requirements.md` records client-observed discrepancies, including revoked WebSocket handshake 403 vs documented close 4401, and should remain labeled as app-side evidence.

## Inspection limits / unknowns

GitHub read-only repository tools were used against the pinned Android commit; source was not cloned or built and screens were not executed. The linked server contract was read at its current default branch, not at a separately pinned server revision; server implementation and deployed behavior were not independently validated. This audit covers Android behavior, not pixel-level parity or the iOS implementation. Compare the iOS implementation to mark each item implemented, missing, or divergent.
